# Поиск автозапчастей и аналогов

Клиентское приложение для подбора запчастей и аналогов через API «Проценка»

**Стек:** React 19, Redux Toolkit, Bootstrap 5, сборка Vite. Без TypeScript.

## Как это работает

Двухэтапный подбор:

1. **Поиск производителей.** Пользователь вводит артикул и нажимает «Найти» (или Enter). Приложение запрашивает все детали с этим номером и показывает список производителей.
2. **Предложения и аналоги.** При выборе производителя отправляется повторный запрос с номером и брендом (`analogues=on`). Результат выводится в таблице: название / производитель, цена, остаток. Искомая деталь идёт первой и выделена, затем её аналоги.

Состояния загрузки (спиннер) и ошибки (сбой сети, HTTP-ошибки, ошибки API, пустой ответ) обрабатываются на обоих этапах.

## Запуск

Требуется Node.js 20+.

```bash
npm install
npm run dev      # режим разработки
npm run build    # production-сборка в dist/
npm run preview  # локальный просмотр сборки
npm run lint     # проверка кода
```

## Настройка

Ключ покупателя задаётся переменной окружения. Скопируйте `.env.example` в `.env` и укажите свой ключ:

```
VITE_API_KEY=ваш-ключ
```

Если переменная не задана, используется демо-ключ из документации (`00000000-0000-0000-0000-000000000001`).

## Структура

```
src/
  api.js                 запросы к API, разбор ответа и ошибок
  store/
    index.js             настройка Redux store
    partsSlice.js        состояние (производители, выбор, предложения) и thunk-и
  components/
    SearchForm.jsx       поле ввода артикула
    BrandList.jsx        список производителей (этап 1)
    OffersTable.jsx      таблица аналогов и предложений (этап 2)
    Loader.jsx           индикатор загрузки
    Message.jsx          сообщения об ошибках и пустых результатах
  App.jsx                раскладка: две колонки, на узких экранах — друг под другом
  index.css              нейтральная палитра поверх Bootstrap
```

## Особенности API

- **Цена.** Поле `price` верхнего уровня помечено в документации как «НЕ ИСПОЛЬЗОВАТЬ». Показывается минимальная цена среди складов, где есть остаток (`от X ₽`).
- **Остаток.** Берётся поле `count` — суммарный остаток по всем складам.
- **Номер детали на втором этапе** берётся из выбранной строки списка производителей, а не из поля ввода: API может вернуть другую запись номера (например, `7160500039/S` для запроса `7160500039S`).
- **Пустой результат.** Если деталь не найдена, API возвращает массив с одной пустой структурой — такие записи отфильтровываются.
- **Большие ответы.** Аналогов может быть сотни, таблица показывает по 50 строк и догружает кнопкой «Показать ещё».
- **HTTP и прокси.** API работает по `http://`, а на HTTPS-сайте браузер блокирует такие запросы (mixed content). Поэтому приложение обращается к `/api/hsprice/` на собственном домене, а прокси перенаправляет запрос на `http://api.favorit-parts.ru/hs/hsprice/`:
  - в разработке и `npm run preview` — `server.proxy` / `preview.proxy` в `vite.config.js`;
  - на Netlify — правило в `public/_redirects`.

  При размещении на другом хостинге нужно настроить аналогичное проксирование `/api/*` -> `http://api.favorit-parts.ru/hs/*`.
